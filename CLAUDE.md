# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project purpose

A URL shortener built as a learning playground for Go, HTTP server best practices, and performance
optimization (see README.md). Functionally complete for its scope: shorten/resolve/list endpoints,
Postgres (primary + read replica), a tiered Redis+LRU cache, Prometheus metrics, Swagger docs, and a
fully containerized dev environment. See `docs/performance.md` for the benchmarking/profiling work
behind the design decisions below.

## Commands

- `make up` — full stack in Docker (app + Postgres primary/replica + Redis + Prometheus + Grafana)
- `make run` — run the app on the host against the same compose-managed dependencies (`go run ./cmd`)
- `make migrate-up` / `migrate-down` / `migrate-create name=...` — schema migrations (golang-migrate), against the primary
- `make swagger` — regenerate `internal/docs` after changing handler annotations
- `make bench-write` / `bench-read` (and `-duration` variants) — `hey`-based load testing, see `docs/performance.md`
- `make test` / `vet` / `fmt` / `lint` / `tidy` — standard Go toolchain wrappers

Configuration is via environment variables (`internal/config/config.go`), loaded from `.env` if
present. Required: `ENV`, `HTTP_PORT`, `LOG_LEVEL`, `DATABASE_URL`, `DATABASE_REPLICA_URL`,
`PG_POOL_MAX_CONNS`, `REDIS_ADDR`.

## Architecture

Dependencies are wired by hand in `cmd/main.go` (no DI framework) — deliberate for this project's
size: `config.New()` → `logging.NewLogger()` → Postgres pools → cache → `shortener.New()` →
`handler.New...()` → `server.New()`.

- `internal/config` — env-based config struct (`caarlos0/env`), `config.New()` returns `(*Config, error)`.
- `internal/logging` — JSON `slog.Logger` to stdout.
- `internal/server` — chi router: `ClientIPFromRemoteAddr`, `RequestID`, `Recoverer`, `Timeout`,
  RED metrics middleware. Mounts the API at `/api`, plus `/metrics` (Prometheus) and `/swagger/*`.
- `internal/handler` — HTTP layer (`shorten`, `resolve`, `list`), decodes/encodes JSON via
  `encoding/json/v2`, maps domain errors to status codes.
- `internal/shortener` — domain logic: `Link`, the `Repository`/`Cache` interfaces the storage and
  cache packages satisfy, base62 code generation with collision retry, and `Resolve`'s
  cache-then-singleflight-then-repo flow.
- `internal/storage/postgres` — `Repo` holds separate primary/replica `pgxpool.Pool`s: `Save` goes
  to primary, `Get`/`List` to replica.
- `internal/storage/memory` — the original in-memory `Repository`, from before Postgres was added.
  No longer wired into `main.go`; kept intentionally as a historical/reference implementation, not
  dead code to be deleted without discussion.
- `internal/cache/lru`, `/redis`, `/tiered` — `tiered.Cache` composes an in-process LRU (L1) in
  front of Redis (L2); write-through on `Shorten`, backfill-on-hit on `Resolve`.
- `internal/metrics` — RED HTTP middleware, a `pgxpool.Stat()` collector (computed at scrape time,
  not polled), and custom counters (`cache_lookups_total`, `shorten_code_collisions_total`,
  `resolve_dedup_total`).
- `internal/docs` — generated by `swag`; don't hand-edit, run `make swagger` instead.

### Notable deliberate choices (don't "fix" without reason)

- `middleware.ClientIPFromRemoteAddr` in `internal/server/server.go` assumes no reverse proxy/LB in
  front of the server. If one is introduced, switch to `ClientIPFromXFFTrustedProxies(n)` — see the
  comment at the call site.
- HTTP server timeouts are tuned for a small-request/small-response profile — see the comments on
  the constants in `internal/server/server.go`.
- `config.New()` returns an error rather than panicking.
- Postgres pool size (`PG_POOL_MAX_CONNS`) is set explicitly via `pgxpool.ParseConfig` +
  `MaxConns` in `postgres.Connect`, not via a `pool_max_conns` DSN query param — that param is a
  pgxpool-only convention that breaks any other tool sharing the same DSN (`migrate`, `psql`).
- `Shortener.Shorten` retries on a code collision (bounded, `maxShortenAttempts`) instead of
  surfacing it to the client.
- `Shortener.Resolve` wraps the cache-miss path in `singleflight` so a burst of concurrent requests
  for the same newly-hot code hits the DB once, not once per request.
